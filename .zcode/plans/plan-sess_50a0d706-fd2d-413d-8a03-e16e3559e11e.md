# OrbSleep 多运行时改造（P0 全量）— 自主执行计划

## Context
将 OrbSleep 从"单 OrbStack + Compose 专用"升级为通用容器按需休眠管理器：多 Docker 环境并行（OrbStack+Colima 实测）、非 Compose 容器（docker run/GUI/API 创建）可安全接入、能力诚实标注。远程 Docker 本轮标记不支持；Podman/containerd/K8s 仅识别展示、不假装支持。保持 AGENTS.md 全部事务铁律与 OrbStack 既有行为。

## 探索结论（已确认）
- `scan/classify.go:164` `no_compose` 是唯一排除点；其余 blocker（host 网络、auto_remove、低端口、IPv6、UDP-only）对新策略同样适用。
- `dockerx` 无 `/containers/create`；inspect 类型子集过窄，需扩展为完整映射。
- 重建唯一路径是 `docker compose up --force-recreate`（12 处调用）；txn payload 以 compose 字段为键。
- 服务已按 socket 钉住（`services.docker_socket`），但引擎单客户端、单代理容器、reconcile 裁剪外环境路由。
- 代理容器挂 `/var/run/docker.sock`（`proxy.go:282`）、单端口范围；多环境需每环境独立代理与不相交端口段。
- GUI 无环境页；协议为单环境模型（Status/ScanResult/Health 各含一个 Context）。

## 架构
### 1. `core/internal/runtime/`（新）
- `runtime.go`：`Runtime` 接口（Info/Ping/List/Inspect/Stop/Start/Remove/Create/Rename/NetworkConnect/Events/Capabilities）；`Capabilities` 结构（List/Inspect/StartStop/Recreate/Events/PortTakeover）——不具备的能力返回 false，不假装。
- `dockerapi/`：唯一实现，按 endpoint 参数化（所有 Docker 兼容引擎共用）；扩展 `dockerx` client 增加 create/rename/network-connect/完整 inspect 类型。
- `discovery.go`：探测清单泛化 —— `ORBSLEEP_DOCKER_SOCKET`、`DOCKER_HOST`、全部 `~/.docker/contexts/meta`（health.go 已有枚举）、OrbStack、Docker Desktop、Colima（`~/.colima/*/docker.sock`）、Rancher（`~/.rd/docker.sock`）、Finch、Lima、Podman（`~/.local/share/containers/podman.sock` 等）、自定义。kind 由 `GET /version` 的 Components/引擎标识 + socket 路径判定（orbstack/docker-desktop/colima/rancher/finch/lima/podman/docker-engine/custom/remote）。
- `registry.go`：环境注册表（state 持久化 + 客户端 map，替换引擎单客户端 + generation）。

### 2. `core/internal/deployment/`（新，创建方式适配层）
- `strategy.go`：`Strategy` 接口（Snapshot/RemoveTakeoverPorts/VerifyDetached/Restore/Describe）。
- `docrun/`（重点新实现）：
  - **完整快照**：inspect → `ContainerSpec` 显式字段映射（Config 全字段、HostConfig 全字段含 Resources/Ulimits/Sysctls/LogConfig/SecurityOpt、NetworkingConfig），存入 txn payload + 服务备份目录；指纹（规范 JSON sha256）用于外部篡改检测。
  - **安全重建序列**：持久化快照 → stop 原容器 → rename 原容器为 `<name>.orbsleep-backup-<ts>`（保留作回滚锚点）→ create 新容器（去掉被接管的 TCP 端口）→ start → 验证 → 成功后才 remove 原容器。任一步失败回滚 = 删新容器 + rename 回原名 + start。
  - **匿名卷保数据**：Mounts 中 64-hex 匿名卷按原名显式挂载（与 Compose recreate 行为一致）；具名卷/绑定天然保留；多网络先建主网络再 ConnectNetwork 恢复别名。
  - 新 blocker：`pid_mode_container`/`ipc_mode_container`；links/storageOpt 等降级为 warning。
- compose 路径：**不改包、不动既有代码**，在 engine 内以同接口薄封装（composeStrategy 内部调用现有函数），保证行为字节级不变。

### 3. 多环境并行
- state：新增 `environments` 表 + `PRAGMA user_version` 真迁移；`services` 加 `environment_id`、`strategy` 列（回填 compose/主环境）；docrun 原始快照入备份目录。
- 引擎：客户端 map 按 envID；reconcile/eventsLoop 按启用环境并发；删除"外环境路由裁剪"（env 启用时）。
- 代理：每环境独立 compose 项目/容器名/socket 挂载/admin 端口；端口段按环境不相交分配（首环境沿用现有全局段保证升级兼容）。
- 设置：全局默认 + 每环境端口段持久化于 environments 行。

### 4. 协议（PROTOCOL.md 唯一契约，同步改 model/api/Models.swift/文档）
新增：`environments.list/add/action(enable|disable|test|remove)`；`scan` 可选 `environmentId`；Container 增 `environmentId/strategy/source`；PlanItem/Service/Status 增 `strategy/environmentId`、`environments[]` 状态列表；Health.protocolVersion→2（帧 v 仍 1，纯增量）。GUI：新「容器环境」页（发现/启停/添加 socket/测试/诊断/每环境代理状态）、扫描与服务列表显示来源/运行时/能力/不支持原因。

### 5. 测试与验收（全部要跑）
- 单测：ContainerSpec 映射金样（真实 inspect JSON fixtures）、分类、发现、端口段分配、phase 迁移矩阵扩展。
- `scripts/phase2_docrun.py`（新，OrbStack 实测）：docker run 创建（binds/具名卷/匿名卷/自定义网络/restart 策略/env/labels/healthcheck）→ 接入 → 休眠 → 唤醒 → 空闲停止 → 恢复 → 配置全等比对；故障注入（create 失败回滚、rename 后崩溃、create 后崩溃恢复）。
- `scripts/phase3_multienv.py`（新）：OrbStack+Colima 并行接入、独立休眠唤醒、单环境离线韧性、端口段不相交、跨环境端口冲突。
- `make build-core / test / app / swift-check / phase0 / phase1` 全绿。

## 验证
- 每阶段 `go build ./... && go test ./...`；提交前 `make build-core test app swift-check phase0 phase1 phase2 phase3`。
- 真实验收以 phase2/phase3 脚本输出为准：完整走通 扫描→接入→休眠→唤醒→恢复，包括非 Compose 容器与双环境并行。
